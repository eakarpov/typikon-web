Одной перестановки целых библейских стихов недостаточно: Триодь местами
переиначивает и соединяет фразы внутри стиха. Например, заключение Михея
в богослужебной редакции не воспроизводит целиком стандартный текст5:4.
Не следует добавлять лишние слова, чтобы подогнать его под стиховую разметку.
Поэтому для шести чтений сохранено отдельное точное богослужебное тело.
Источник в JSON нормализован только по пробелам, включая ударение, отделённое
HTML-тегом от местоимения; состав и порядок слов сохраняются.

Фиксация текста, SHA256 исходников/тел, порядок и постоянные новые ID:
`src/scripts/data/composite-paremias.json`. В новых документах зачал:

- `source: "paremia"`, `bookSlug` и `ranges` дают параллельные библейские ссылки;
- `liturgicalText` содержит язык `cs`, название и URL источника, точное `content`;
- `referencesOnly: true` явно указывает, что диапазоны не задают тело чтения.

`resolvePericopeVerses` для такого документа возвращает богослужебный текст,
без выдуманных стиховых ID, привязки к изданию Библии или ложного разбиения на
стихи: `verses: []`, `textId: null`, `editionCode: null`. Сайт показывает текст
Триоди; API и OpenAPI предоставляют `liturgicalText.content` и объясняют этот
формат. Потребителям этих новых зачал нужно читать это поле, а не собирать
текст повторно по `ranges`. Старые каталожные документы не меняли формат.

`resolvedLang`; непроверенный перевод не подменяется смесью библейских стихов.
Если богослужебное тело повреждено, полные стихи не возвращаются вместо него.
