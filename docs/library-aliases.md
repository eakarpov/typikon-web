## Как сохраняются ссылки

`_id` книги/текста постоянен; связи, закладки и прогресс чтения продолжают
использовать его. `alias` — нынешний адрес, `aliases` — массив всех зарезервированных
адресов, включая нынешний. Пустой нынешний алиас означает канонический адрес по ID,
но прежние элементы `aliases` всё равно разрешаются в тот же документ.

Поиск принимает ID, нынешний или прежний алиас. При открытии страницы по другому
адресу сервер переводит на нынешний, сохраняя query-параметры, включая повторные
значения и `accents=1`. Location не содержит фрагмента: браузер сохраняет исходный
`#…` при HTTP-переходе. Для изменяемых алиасов используется **307**, чтобы возврат
к прежнему имени или снятие алиаса не создали петлю из сохранённых браузером
постоянных перенаправлений. В метаданных задан канонический адрес.

Старые ID и новые алиасы библейских карточек библиотеки по-прежнему ведут в
`/bible?v=<код издания>`; код издания берётся из базы и имеет приоритет над старым
параметром `v`. Этот существующий постоянный переход остаётся 308.

Адрес книги редактируется в админке. Адрес текста — в прежнем редакторе.
Содержимое и история сохраняются одним обновлением с проверкой, что другой
редактор не успел сменить адрес. Конфликт возвращает 409 и не сохраняет остальную
правку. Новый адрес проверяется на формат и занятость среди нынешних и прежних;
для текстов также зарезервированы `random` и адреса прежних библейских книг.

Индексы `books.alias`, `texts.alias` уникальны для непустых строк. Уникальный
multikey-индекс `aliases` в каждой коллекции защищает общее пространство нынешних
и прежних адресов. Алиасы книг и текстов имеют отдельные пространства маршрутов.
История включается в обычный дамп этих коллекций, а индексы описаны также в
`ensure-indexes.ts`. При импортах нужно сохранять `aliases`; не заменять запись
произвольным документом без истории.

Ссылки библиотеки, оглавления книги, обратная ссылка из текста и sitemap используют
нынешний алиас с запасным ID. API v2 книг/текстов и мест текста, а также старый
API v1 текстов принимают прежние алиасы. В JSON книги добавлено `alias`, поле `id`
не изменилось. Связи статей Никифора также разрешают прежние адреса.

## Локальная миграция и выкладка

```sh
npx tsx src/scripts/migrate-library-aliases.ts          # проверить план
npx tsx src/scripts/migrate-library-aliases.ts --apply  # копия метаданных, индексы, запись
```

Скрипт разрешает подключение только к loopback MongoDB и работает с `typikon`.
Сначала проверяет коллизии обеих коллекций, затем создаёт резервную копию
метаданных адресов в игнорируемом `scratch/alias-backups/`, создаёт индексы и
применяет план. Уже имеющиеся алиасы не генерируются заново из названия.
Длинные заголовки нескольких записей получили явно заданные короткие адреса.

Копия этого прогона:
`scratch/alias-backups/2026-10-30T20-25-07-667Z.json`.
В ней — ID, прежние поля `alias`/`aliases`/`updatedAt` и назначенные адреса;
тел текстов и пользовательских данных нет. При необходимости восстановления
нужно сравнить текущее состояние с `after`, чтобы не затереть последующие правки.

Для публикации нужны и новый код, и свежий дамп локального корпуса с полем
`aliases` и индексами. Один выпуск кода не создаст адресов на сервере, а дамп,
снятый до миграции, их не содержит. Серверного запуска миграции не требуется.
После выкладки проверить старый ID, новый алиас, библейскую карточку и сброс кэша.
При последующих переименованиях пользоваться редактором с `saveWithAlias`;
старый `fix-duplicate-aliases.ts` не сохраняет историю и для этой задачи не подходит.

## Проверка

- Типизация; тесты подвижного/лекционарного круга, сериализации API, алиасов и
  затронутых связей мест.
- Интеграционный тест на отдельной временной локальной БД: переименование,
  сохранение старого адреса, запрет его занятия другой записью, откат конфликтной
  правки, снятие алиаса и конкурентное занятие одного адреса.
- Локальные HTTP-проверки: ID книги → 307 с обоими `tag`; новый адрес → 200;
  ID текста → 307 с `accents=1`; библейская карточка → 308 с `v=cs-eliz`;
  первый час и его ссылка/паремия присутствуют в HTML; API дня Святого Духа и книги
  по алиасу отвечают 200 с правильными данными.
- В браузере проверена старая ссылка текста с `?accents=1#p-0`: после перехода
  на нынешний алиас сохранены и параметр, и фрагмент; сам текст отображается.
