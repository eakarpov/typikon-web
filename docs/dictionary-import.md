# Подготовка словаря Chu Rus и восстановление раздела я

Подготовка создаёт отдельную SQLite-базу свидетельств. Она не подключается к MongoDB, не переписывает lexems и не меняет существующие ID, схемы или исправления. Раздел я экспортируется отдельно для последующего добавочного импорта.

## Запуск

Из typikon-web с установленными зависимостями:

```sh
node --import tsx src/scripts/prepare-chu-rus.ts \
  --dsl ../cs-app/Chu-Rus_Reference_v3.dsl.dz \
  --lexems csl-db/typikon-csl/lexems.bson \
  --out ../cs-app/import/chu-rus.sqlite
```

Принимается BSON-дамп или JSON-массив lexems с исходными ID. Перед будущим применением нужен свежий снимок реальной базы: локальный дамп не заменяет серверные исправления. При существующем выходном файле скрипт отказывает, файл не удаляется. Поддерживается UTF-8 DSL, включая gzip/dictzip, BOM, CRLF и несколько заголовков статьи. UTF-16 требует явного предварительного декодирования.

Результаты: SQLite со статьями, положениями в файле, фрагментами по источникам, грамматическими связями и предложениями соответствий; .recovery-ya.json с леммами и формами; .summary.json со сводкой. SHA-256 исходного файла и снимка сохраняются в metadata, baseline содержит ID и контрольную сумму каждой исходной записи. state=complete устанавливается только после окончания подготовки. Повреждённый вход не получает этот статус.

## Сохранение идентичности

В links.lexemeId сохраняется typikon ObjectId. Точное сопоставление различает ѣ/е, і/и, ѡ/о и ударения; позиционные начертания и звательце нормализуются. Гражданский ключ даёт только кандидатов. Омонимы с суффиксом _2 не связываются по порядку записей.

Идентификаторы статей и блоков зависят от содержимого и пространства источника; исходные позиции сохраняются отдельно. Новая версия источника добавляет свидетельство, не стирая старое. Редакторские решения должны храниться отдельно от вычисляемых предложений и переживать повторный импорт.

Предполагаемые Mongo-коллекции: dictionarySources, dictionarySourceVersions, dictionarySourceEntries, dictionarySourceFragments, dictionarySourceLinks. Эта подготовка их не создаёт. Каждый фрагмент сохраняет метку источника, например Дч*. Библиография и условия распространения уточняются в dictionarySources; до этого не считается, что весь материал разрешён к публичной выгрузке.

## Восстановление я

Заголовочная форма берётся из действительного церковного заголовка DSL, сопоставленного с указателем леммы. Формы извлекаются из связей gr с sourceEntryId и исходными грамматическими пометами. ID новой лексемы детерминирован по пространству источника и ключу леммы, включая номер омонима.

Схемы, отсутствующие в DSL, не выводятся по окончанию. Для изменяемого слова morphologyStatus=unassigned, scheme=""; для известных классов неизменяемых — notApplicable. Если заголовок источника не найден, orthographyStatus=needs-review: кандидат не публикуется автоматически.

Оригинальный сайт словаря Полякова по HTTP и HTTPS не ответил при подготовке. Для восстановления его кодов схем нужен доступный исходный раздел. DSL восстанавливает леммы и выписанные формы, но не эти коды.

Будущее применение должно заново прочитать текущую базу, сохранить найденные ID, отдельно разобрать конфликты и вставить только отсутствующие записи с происхождением. Старый dictionary-load.js с deleteMany не используется. Перед публикацией нужно дополнить экран словаря: существующий интерфейс пока не различает пустую схему неизменяемого слова и неустановленную схему изменяемого.

## Пометы

Ось называется «извод». Начальные значения: русский синодальный и русский дониконовский (старообрядческий); модель допускает украинский, сербский и хорватский. Дата памятника и принадлежность конкретного издания традиции хранятся в источнике. Глаголическое письмо не подменяет извод.

«Устаревшее» — основная помета, архаизм/историзм — необязательное уточнение. Оценка относится к определённому периоду и изводу. См. [объяснение различия](https://gramota.ru/journal/stati/zhizn-yazyka/ustarevshie-slova-v-leksike-sovremennogo-russkogo-literaturnogo-yazyka).

Внутренняя классификация различает церковнославянские, старославянские, древнерусские и русские свидетельства. Это отбор источников, не этимология и не обязательный пользовательский фильтр. Русизм, балканизм и западнославянизм — отдельные проверяемые признаки формы, значения или написания.

## Церковное написание

Пользовательский словарь показывает церковное написание. Гражданская форма сохраняется как свидетельство и поисковый ключ. Каждая опубликованная форма получает church, подтверждённое источником, словарной связью или редактором. csCanonical и позиционные правила не восстанавливают утерянные ѣ/е, і/и, ѡ/о и ударения.

Непроверенная гражданская форма остаётся в очереди с church=null. Публичная выгрузка исключает такие формы. Гражданское и глаголическое представления могут строиться поверх канонического написания, не создавая дополнительных лексем.

## Этимологии в interlex

Typikon-web хранит ProtoReference: provider=interlex, articleId, отношение к слову/морфеме, статус проверки и основания связи. Допускаются несколько proto-ссылок. Содержание, реконструкции, библиография и исправления остаются в interlex. Мобильный кеш допустим как копия, не как независимый источник.

В локальном interlex.db — 24 531 запись proto_slavic_words с полями id, lemma, body, source_url. Не каждая запись является одной реконструкцией: первая представляет обзор группы на C. Соответствия требуют проверки содержания. Межславянская привязка не устанавливает этимологию церковнославянской лексемы автоматически.

В interlex уже есть GET /api/public/v1/proto и /api/public/v1/proto/{id}. Текущий вариант требует Bearer API key; до подключения Flutter нужно определить мобильный доступ. Серверный ключ не встраивается в приложение. Новый endpoint в этой задаче не создаётся.

Typikon-web впоследствии отдаёт protoReferences, а Flutter получает подробности у interlex отдельно; недоступность этимологий не блокирует словарь. При объединении proto-статей interlex сохраняет прежние ID или перенаправляет их на актуальный ID.

historical.db — отдельный слой свидетельств: 1 551 документ, 31 848 предложений, 280 007 токенов. Источники документов: 1 206 берестяных, 322 старославянских PROIEL, 23 балканских. Существующие 9 955 HistoricalAttestation используют lexemeId межславянского словаря, не typikon: их нельзя переносить напрямую. Историческая фиксация сама по себе не равна праформе или доказанной этимологии.

## Проверки

```sh
node --import tsx --test src/lib/dictionaryImport/*.test.ts
npx tsc --noEmit --incremental false
```

Тесты проверяют сохранение ID и локальной схемы, различение омонимов и графики, происхождение фрагментов, стабильность новых ID и отсутствие выдуманных схем. Полный прогон дополнительно сверяется по количеству статей, лемм и восстановленных слов.


## Актуальное состояние

Разбор 12 заголовков, 11 реконструированных схем, оставшихся 114 кандидатов и безопасного применения описан в [dictionary-review.md](dictionary-review.md). Исходные 142 ID сохранены. В рабочую MongoDB данные ещё не записывались.

## Общая лексема для разных изводов

Основной словник typikon-web и грамматический слой Chu-Rus в этой подготовке по умолчанию относятся к русскому синодальному изводу. Источники исторических примеров сохраняют собственные характеристики: этот default не переопределяет исторические документы interlex.

Лексема имеет один устойчивый ID, а OrthographyVariant хранит её написание, извод, область lemma/form, свидетельства и статус проверки. Например, чꙋдо и чюдо связываются с одной лексемой через две записи написаний. Несколько написаний допустимы и внутри одного извода.

LexemeMatcher принимает проверенные варианты с непустыми evidenceIds. Чужой извод не получает точного соответствия только из совпадения букв; сначала нужна подтверждённая связь. Непроверенная запись не создаёт автоматического соответствия. Общая замена ю/у не применяется, варианты исходного текста не уничтожаются. Для словоформ дополнительно сохраняются грамматические признаки: общее слово не означает, что все формы и парадигмы разных изводов совпадают.
