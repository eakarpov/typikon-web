# Публикационный словарь для «ЦС Словаря»

Новые обработчики `/api/v2/cs/search`, `/lexemes/{id}`, `/source-entries/{id}`, `/reports` не заменяют старый словарный API. Чтение не требует ключа. Контракт добавлен в общий OpenAPI v2. Этимологии читаются отдельно из interlex `/api/public/cs/proto/{id}`.

## Данные

`CS_DICTIONARY_DB` — абсолютный путь к завершённой версионированной SQLite. Отсутствие или незавершённость публикации даёт 503. Веб-процесс открывает файл только для чтения и принимает только публикацию с `scopeChecked=1`. Перекрёстные ссылки DSL выделены в `relatedSources`; их объяснения не индексируются как значения текущей лексемы. Неоднозначно сопоставленные источники не попадают в индекс переводов или семантики. MongoDB нужна только обработчику явно отправленного сообщения: коллекция `typikon-csl.dictionaryContentReports`. Необходим доступ на запись в эту коллекцию.

Публикация содержит исходные ID и отдельно подготовленное представление. Гражданское исходное написание сохраняется в `originalName`, церковное отображение — в `name` и формах. Восстановленные заголовки могут быть опубликованы при неизвестной парадигме. Восемь технических пустых/служебных записей не отображаются; из исходной базы они не удаляются. Импорт MongoDB, переназначение ID и исправление схем этот pipeline не выполняет.

Из исходного DSL создаются безопасные текстовые абзацы и ссылки без HTML. Нумерованные значения сохраняются; ненумерованный блок имеет статус `unsegmented` и не является одним значением. Явные эквиваленты в таком блоке получают отдельные `source-fragment` с собственными ID и версией источника. Номера библейских ссылок, заголовки составных выражений и проза определений не объявляются переводом.

ID фрагмента зависит от источника и содержимого, но не от общей версии импорта: повторная загрузка неизменённого материала сохраняет адрес. Если изменился сам подтверждённый фрагмент, финализатор останавливается на потерянной редакторской связи; её нужно пересмотреть.

`src/data/csDictionary/review.json` хранит принятые связи, отклонённые ID и проверенные этимологические свидетельства. Это редакторский слой, независимый от повторяемых предложений. Автоматическое обогащение не меняет его. RuWordNet используется через экспорт справочника; межславянские Meaning/semantic_relations не копируются. Антонимия возможна только по явному отношению справочника. Этимологические кандидаты никогда автоматически не публикуются. Опубликованные proto-ссылки означают проверенное свидетельство, не доказательство прямого наследования.

## Подготовка

Нужен Node 22, Python 3, зависимости проекта. В командах ниже рабочая папка — typikon-web; все выходные пути должны быть новыми. Папка `cs-app/import` содержит проверенные локальные входы и исключена из Git. Файлы не включаются в APK.

```sh
node --import tsx src/scripts/build-cs-publication.ts \
  --snapshot ../cs-app/import/current/lexems.json \
  --staging ../cs-app/import/chu-rus.sqlite \
  --plan ../cs-app/import/plan-current-final.json \
  --recovery ../cs-app/import/recovery-ya.reviewed.json \
  --out /absolute/path/base.sqlite

node --import tsx src/scripts/finalize-cs-publication.ts \
  --base /absolute/path/base.sqlite \
  --out /absolute/path/sources.sqlite \
  --refresh-sources ../cs-app/import/chu-rus.sqlite \
  --scope-sources ../cs-app/import/chu-rus.sqlite \
  --plan ../cs-app/import/plan-current-final.json \
  --recovery ../cs-app/import/recovery-ya.reviewed.json
```

Первый шаг проверяет ID плана и отпечатки исходных материалов, создаёт поисковый индекс лемм/форм/засвидетельствованных графических вариантов и русских эквивалентов. Второй шаг предпочитает точно сопоставленное засвидетельствованное церковное написание. Для производных старого прототипа без индекса вариантов предусмотрены `--aliases-from`, `--plan`, `--recovery`; для новой сборки это уже сделано в build.

Экспорт RuWordNet выполняется скриптом interlex `scripts/export-cs-semantics.py`. Затем:

```sh
python3 src/scripts/enrich-cs-publication.py \
  --publication /absolute/path/sources.sqlite \
  --semantics ../cs-app/import/cs-ruwordnet.json \
  --interlex ../interlex/interlex.db \
  --out /absolute/path/proposals.json

node --import tsx src/scripts/finalize-cs-publication.ts \
  --base /absolute/path/sources.sqlite \
  --out /absolute/path/release-VERSION.sqlite \
  --proposals /absolute/path/proposals.json \
  --decisions src/data/csDictionary/review.json \
  --provenance ../cs-app/import/provenance-v1.sqlite

node --import tsx src/scripts/validate-cs-publication.ts \
  --publication /absolute/path/release-VERSION.sqlite \
  --snapshot ../cs-app/import/current/lexems.json \
  --out /absolute/path/acceptance.json
```

Финализатор делает новую копию; исходный файл не меняет. Только после проверки связей, присоединения учёта источников и завершения транзакций выставляет `state=complete`. Рядом сохраняется JSON с SHA-256, версией и количествами. Происхождение лексем/форм/схем переносится из единого provenance; несовпавшая схема не получает атрибуцию старой схемы. Неизвестное происхождение отмечается явно. Сгенерированная форма ссылается на происхождение схемы.

## Активация и откат

1. Сохранить текущий путь, контрольную сумму публикации и коммит кода. Если меняется только этот слой, резервная копия канонической MongoDB не заменяет копию публикационного файла; сам pipeline MongoDB не пишет.
2. Загрузить новый файл под новым именем в общий каталог данных вне release worktree. Сверить SHA-256 с JSON, `PRAGMA quick_check`, `metadata.state=complete`, версию, контрольные запросы, прежние ID и локальные поля. Сохранить предыдущий файл.
3. Указать новый абсолютный `CS_DICTIONARY_DB` в серверном окружении, выполнить обычный релиз кода проекта и перезапуск процесса. Нельзя подменять файл за тем же путём в работающем процессе: соединение кешируется.
4. Проверить реальные HTTP-ручки с телефона, межсервисный отказ, отчёты, CORS и нагрузку. Публичная публикация APK Уставных чтений и его version endpoints сюда не входят.
5. Откат — предыдущий коммит и прежний путь к SQLite с перезапуском. Сообщения пользователей в MongoDB при откате кода не откатываются.

Лимиты нового приложения: поиск 300/мин, детали 600/мин, сообщения 5/час на IP процесса. Ответ 429 содержит Retry-After. При нескольких процессах нужен общий лимит на reverse proxy; текущие счётчики внутрипроцессные. Слишком короткий запрос старого API не влияет на новый: один символ — точное совпадение, от двух — префикс.

## Проверки

`npm run typecheck`, `npm test`, затем validator на реальных данных. Последний проверяет 480 запросов обоих направлений, прежние ID/локальные поля, точное восстановление сегментов и адресуемость смысловых связей. Локальный p95 SQLite не заменяет p95 HTTP на стенде. Редакторская проверка смысла и физические Android/iOS-устройства остаются обязательной частью закрытой приёмки.
