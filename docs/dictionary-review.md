## Реконструкция схем

Из 125 изменяемых записей у 11 найден единственный код из реализованных таблиц, совпадающий со всеми проверяемыми выписанными формами. Это реконструкция по формам и аналогам текущего словаря, не получение подлинного кода из недоступного первоисточника. Ударения при сравнении не проверялись. Проверка не доказывает правильность всех непредставленных форм.

## Общая модель слитной формы

Модель хранит целую засвидетельствованную форму и её компоненты с ролями, грамматическими признаками, ID статей и источниками. Базовый компонент может быть разорван энклитикой; порядок принадлежит отдельной форме, а не всей парадигме. Неподтверждённые варианты разбора остаются кандидатами. Краткая форма ведёт к существующей статье соответствующей лексемы, а не автоматически создаёт новую лемму.

В семи сочетаниях раздела я сохранена композиция. Пока её отображение и ссылки на все базовые статьи не готовы, эти записи удержаны от публичного канонического импорта.

## Что сохранено из Chu Rus

Полностью сохранено сырьё 410 059 статей и 858 538 блоков по источникам, все заголовки и исходные положения. Дополнительно выделены 833 080 внутренних ссылок, 42 319 библейских указателей, 198 991 частотная запись и 222 несвязанные грамматические пометы. Ссылки на единственный медиаресурс vs.bmp также сохранены; самого BMP в предоставленном архиве нет.

Частота 0 отличается от неизвестной частоты. Частоты пересекающихся подкорпусов не суммируются в общий итог. В восстановленном разделе у 810 форм источник сообщает положительную частоту, у 23 — нулевую, у 43 частота не определена. Это сведения Chu-Rus, не статистика корпуса typikon-web. Техническая помета ':' хранится как sourceProperties и не показывается грамматической характеристикой.

Толкования, переводы, примеры, производные и иноязычные соответствия сохранены в исходных блоках, но ещё не превращены в выверенные отдельные значения общей статьи. Сохранение полного сырья не равно завершению лексикографической редакции. Имена авторов/издания и разрешения на повторную публикацию уточняются по источникам.

## План на актуальную базу

С production снят read-only архив lexems: 33 985 записей. По ID и всем полям он совпал с прежним локальным дампом. Последующий read-only preflight вновь подтвердил fingerprint плана.

План содержит 28 канонических вставок, 114 удержанных записей и 34 116 предложений связей. Существующие леммы не обновляются и не удаляются. Исходные свидетельства импортируются отдельно через setOnInsert; повторный запуск не затирает редакторские поля.

До применения необходимо выложить читатель с поддержкой morphologyLemma. Церковный заголовок остаётся в name, а внутреннее написание исходного грамматического словаря — в morphologyLemma. Без этого, например, окончания с ї и юсом могут неверно обрабатываться существующими таблицами. На production при preflight этой возможности ещё не было. Версия Android и эндпойнт обновлений в этой задаче не меняются.

Скрипт apply-chu-rus.ts по умолчанию делает dry-run и требует явного имени переменной с URI. Он проверяет хеш плана, базы подготовки и fingerprint всех существующих лемм. Перед --apply обязательны подтверждение развёрнутой capability и новый каталог резервных копий. Копии сохраняют типы BSON через Extended JSON. Каноническая запись выполняется insertMany с заданными ObjectId, без update/delete/replace. При новых правках нужен свежий план; при незавершённой собственной попытке требуется явный --resume. История резервных копий сохраняется.

## Команды

Подготовка структурированных свидетельств:

```sh
node --import tsx src/scripts/structure-chu-rus.ts --staging ../cs-app/import/chu-rus.sqlite --dsl ../cs-app/Chu-Rus_Reference_v3.dsl.dz
```

План на свежий JSON-снимок:

```sh
node --import tsx src/scripts/plan-chu-rus.ts --staging ../cs-app/import/chu-rus.sqlite --snapshot ../cs-app/import/current/lexems.json --recovery script-data/dictionary/recovery-ya.chu-rus.json --out ../cs-app/import/new-plan.json
```

Проверка на сервере после подготовки файлов и окружения, без записи:

```sh
node --import tsx src/scripts/apply-chu-rus.ts --plan /path/to/plan.json --staging /path/to/chu-rus.sqlite --mongo-uri-env DICTIONARY_MONGODB_URI
```

Запись не запускалась. Для неё отдельно добавляются --apply, --runtime-capability dictionary-morphology-lemma-v1 и --backup-dir /path/to/new-backup-dir после выпуска совместимого читателя. URI не передаётся аргументом и не печатается. Полная база свидетельств большая; её переносится с проверкой SHA-256, а план создаётся заново при изменении артефактов или текущих лемм.

## Дополнение проверки полноты

Исправлен разбор 139 числовых заголовков на #. Четыре из них — самостоятельные статьи, которые прежняя подготовка склеивала с соседними; остальные — дополнительные алиасы. После повторной проверки: 410 059 статей, 627 386 строк заголовков, 614 964 уникальных заголовка, 858 538 блоков источников. Исходные тексты не утрачены; восстановлены границы статей и поисковые варианты. Ни один из 142 ID восстановления не изменился. Старые планы автоматически отклоняются по хешу промежуточной базы.

Редакционные решения сохранены отдельно в src/data/dictionary/recovery-review.json, чтобы их можно было версионировать вместе с кодом. Генерируемые массивы в script-data не заменяют этот слой решений. Неподдерживаемые текущим генератором коды также включены в кандидаты по существующему словарю: отсутствие таблицы не означает отсутствие схемы. Кандидаты по совпадению окончания не выдаются за доказанную морфологическую или этимологическую связь.

При исправлении границ одна ссылка восстановленного слова на исходную статью пересвязана на её корректный ID. Это ID свидетельства, а не лексемы; все 142 ID лексем сохранены. Все 876 ссылок форм на источники проверены после пересвязки.
