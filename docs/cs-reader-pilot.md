# Корпус ЦС: пилот Э1-08

Реализация от 2026-11-14. Вход только через `/opyty/cs-reader` и карточку
в `/opyty`. Главная, основная навигация и sitemap не меняются.
У пилота meta robots `noindex,nofollow`, у `/sources/**` также HTTP
`X-Robots-Tag`. Это экспериментальный reader, а не новая копия библиотеки.

## Хранилища и публикация

`src/data/reader/pilot.json` содержит пять nativeRef и редакторские свидетельства.
Текст читается из существующих Mongo `texts` и readonly SQLite `RULES_DB`.
Новый реестр хранит привязки, дескрипторы, паспорта, профили, постоянные ID
и историю публикаций. Поля content/rawText/viewText в него не копируются.
Проекции, карты и токены вычисляются при чтении.

Материалы: крестовоскресный канон Октоиха (глас 1, 40 вхождений), акафист
Николаю (25 строф), первая беседа Маргарита, ссылочный ирмос из выбранного
канона и тропарь «Правило веры». Ирмос использует те же occurrenceId/bodyId,
что его вхождение в каноне; тело остаётся в `fixed_texts`. Родной канон неизвестен.

Исторические сведения передаются утверждениями, наблюдениями и открытыми
вопросами. Атрибуция канона не превращается автоматически в проверенный факт;
авторство главы не выводится из имени автора всего сборника. Технические даты
не выдаются за даты создания или перевода. Статус главы `texted` сохранён.
Права источников пока `unresolved`, общей лицензии на новый reader не назначено.

Требуется Node 22 с Unicode 16; версии Unicode и таблиц входят в ProfileSet.
Изменение профиля требует нового ID. Веб-процесс должен видеть исходные
MongoDB и SQLite; доступ к RULES_DB только на чтение.

```sh
# Проверка без записи. По умолчанию env-скрипты используют production,
# поэтому для локального пилота NODE_ENV задаётся явно.
NODE_ENV=development node --import tsx src/scripts/reader-publish.ts

# Подготовить и атомарно включить публикацию в локальной MongoDB.
NODE_ENV=development node --import tsx src/scripts/reader-publish.ts --apply --activate

# Проверка с существующей завершённой публикацией словаря:
NODE_ENV=development CS_DICTIONARY_DB=/absolute/path/publication.sqlite \
  node --import tsx src/scripts/reader-verify.ts --report /tmp/reader-verification.json

# Откатить только указатель на ранее активированную публикацию:
NODE_ENV=development node --import tsx src/scripts/reader-publish.ts \
  --rollback release1_HASH --apply
```

Оба скрипта разрешают запись только в локальную MongoDB. Production-релиз
в этой задаче не выполнялся; перенос реестра должен сохранять назначенные ID,
а не генерировать их заново независимо на каждом окружении.

## Контракт и адреса

Префикс `/api/v2/study/reader/v1`: GET capabilities/catalog/passport/{sourceId}/search;
POST resolve/read/lookup; OPTIONS. Самостоятельная спецификация:
`/api/v2/study/reader/v1/openapi`; схемы также добавлены в общий OpenAPI.
Wire-контракт — `cs-reader/1`, адрес — SourceAddress version 2.
Постоянный URL — `/sources/id/{sourceId}`, slug остаётся алиасом.
Селекторы occurrence/fragment/range взаимоисключающие; ревизии можно закрепить.

Read возвращает полный дескриптор и постраничные тела. rawWindow и rawRanges
абсолютные UTF-16; surfaceRanges и карта view — локальные относительно окна.
Границы не разрезают слово или комплекс знаков. Исходная графика и PUA
сохраняются; неизвестный PUA блокирует словарный ключ. Поиск возвращает короткие
окна с подсветкой; lookup — кандидатов существующего словаря, без автоматической
подмены сокращений развёрнутыми словами. Без завершённого CS_DICTIONARY_DB lookup
возвращает 503, остальные операции работают.

Доступ использует существующий texts scope и квоты API. Запрос ограничен 64 KiB,
ответ 4 MiB, страница чтения 20 вхождениями. Ошибки имеют единый reader-envelope;
ETag поддерживается для публичных GET метаданных.

## Старые адреса и ревизии

При первой публикации фиксируется baseline всех числовых ID SQLite: в локальной
базе 277996 строк, включая 869 неразрешённых ссылок. Это не исправление этих
ссылок, а резервирование их адресов. При новой сборке нужны повторная подготовка
привязок и публикация: сначала сопоставление контекста/тела, затем единственного
неизменного контекста; неоднозначные случаи не угадываются. Незнакомая сборка
не обслуживает старый номер как новый native ID. Новые серверные ссылки на
native строки включают dataset revision.

Pinned тело после правки, удаления или утраты исходной сборки возвращает 410;
latest вместо него не подставляется. Закрытый источник возвращает 404.
Архив тел в MVP не создаётся. Привязка fragment к изменённому телу требует
проверки и не переносится автоматически.

13 заменяемых операций старого reader отмечены deprecated в OpenAPI и HTTP
Deprecation/Link; прежние JSON-форматы сохранены. Срок удаления не задан,
reader Sunset не вводится. Действующие заголовки переезда старого хоста сохраняются.
Словарный API не deprecated. Удаление адаптеров возможно после ухода старых клиентов;
публичные цитатные URL при этом должны сохраниться.

## Проверка

`reader.test.ts` покрывает UTF-16, PUA, карты окон, Markdown, отсутствие
угадывания ID и недоступность прежнего тела после редактирования/закрытия.
`reader-verify.ts` сверяет все семь ответов с согласованным OpenAPI, пять
источников × три профиля, пагинацию, SHA главы, общий ирмос/канон, словарь,
поиск, HTML noindex, ошибки, ETag и идемпотентную повторную публикацию.
