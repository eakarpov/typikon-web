# Выпуск 6.5

Подтверждённый владельцем порядок: личный план чтения, сохранение недели без сети,
режим сосредоточенного чтения, личные подборки, несколько проектов мастерской.
Перевод и интерфейс параллельного чтения Библии не входят в новый объём.
Дополнительно подтверждены «Мой храм» в учётной записи и напоминания по личному
плану. Сайт 6.5 и приложение 2.3.5+15 выложены 2026-10-31; напоминания включены.
[Результат выкладки и эксплуатационные проверки](release-6.5-deployment.md).

## Личный план

Один план на учётную запись в `typikon-users.readingPlans`: последовательность книги
по `bookIndex` и размеченным статиям либо рядовые Апостол/Евангелие подвижного круга.
Личный ряд не подменяет календарные праздничные назначения. Пропущенные дни
не двигают курсор; переход — явной отметкой. Пауза сохраняет место. Смена плана
требует удаления текущего. Версия записи защищает от повторного нажатия из другой
вкладки. Прогресс абзаца остаётся отдельным механизмом.

В `/reading-plan` доступны создание, пауза, возобновление и удаление плана. Блок
на `/segodnya` показывает следующий шаг. Для целого текста используется имеющаяся
отметка абзаца; статия открывается отдельным фрагментом с предыдущей/следующей.
Просмотр статии не перезаписывает прогресс всего произведения. Рядовые зачала
показываются непосредственно в плане; ссылка не уводит в календарный слот,
который на праздник мог быть заменён.

## Чтения без сети

`/offline-readings`: ближайшие семь дней по умолчанию или диапазон до 31 дня,
предварительный состав, наличие данных дня, сохранение/обновление, фактический
список страниц и удаление пакета. Сохраняются полные страницы дней и необходимые
стили, скрипты и шрифты; переход к целому произведению требует его отдельного
сохранения. При недоступном обязательном ресурсе страница не объявляется готовой.

Service worker v4 сохраняет принадлежность страницы нескольким пакетам.
Удаление недели не удаляет день из поездки, другой недели или отдельного сохранения.
Изменения описи сериализованы. Страницы личного плана и API не кэшируются.
При потере связи показывается ссылка на сохранённые чтения; из списка открывается
обычная навигация документа, не требующая незакэшированного RSC-ответа.

## Сосредоточенное чтение

На произведении и странице дня доступна кнопка режима чтения: скрывается основная
навигация, сохраняются выход и настройки. Размер текста, интервал и ширина используют
существующие настройки сайта. В дне можно идти по назначениям по одному, в книге —
по размеченным статиям. Escape возвращает обычный вид и фокус на кнопку.

## Подборки

`/reading-collections`: личные списки в `typikon-users.readingCollections`, до 100
подборок по 200 чтений. Произведение или отдельная статия добавляется со страницы
чтения. Доступны переименование, изменение порядка, удаление пунктов и сохранение
страниц без сети. `/saved-collections` хранит явно сохранённый состав в браузере,
сохраняет порядок и статии, показывает фактическое наличие каждой страницы;
локальная копия открывается без входа и может быть удалена с устройства.
Одновременные правки защищены версией записи.

Публикация по отдельной кнопке создаёт неизменяемый снимок названия и состава в
`readingCollectionShares` с отдельным адресом. Последующее изменение оригинала
не меняет снимок; сами тексты открываются в актуальной редакции корпуса. Владелец
может закрыть опубликованные копии; удаление подборки также закрывает ссылки.
В публичном ответе нет ID владельца. Тексты закрытой книги и несуществующие статии
добавить нельзя. Адреса и подписи определяются сервером, а не входящим запросом.

## Проекты мастерской

Список именованных проектов в `/opyty/kruczie`: открыть, переименовать, сделать
независимую копию, скачать, импортировать, удалить. Хранение — в этом браузере;
старый единственный черновик переносится один раз и сохраняется как резерв.
Каждый проект имеет отдельный ключ, так что открытие другого не заменяет первый.

Файл `.kruczie.json` переносит исходник целиком, выбранные варианты и ручные ноты
с привязкой к позициям, включая незавершённый разбор. Также сохраняются распев,
глас, источник, вид нот, темп и настройка высоты. Это файл проекта; экспорт
законченного нотного произведения в формате znamen.ru остаётся отдельным действием.

## Проверки

- Чистые тесты: переходы ряда и книги, пауза, границы дат и статий, проверка
  ссылок подборок, пересечение пакетов, обязательные ресурсы, перенос проектов.
- Два временных пользователя локальной базы: изоляция планов и подборок,
  гонка двух одинаковых отметок, пауза, порядок книги и восстановление абзаца;
  неизменяемость опубликованного снимка, отсутствие ID владельца и отзыв ссылки.
- Браузер, 390 px: пауза/возобновление, переход из прочитанного текста к следующему,
  режим чтения без горизонтального переполнения, Escape с возвратом фокуса.
- Обычная production-сборка: сохранены все семь дней недели. После остановки
  локального preview день открылся из сохранённого пакета, переход между
  назначениями внутри дня работал без сервера.
- Production-интерфейс мастерской: импорт незавершённого проекта с ручной нотой,
  восстановление гласа, темпа и вида нот, создание отдельной копии и скачивание.
  В скачанном файле исходник, позиции и настройки совпали с исходным файлом.

Это локальная реализация для 6.5. При подготовке выкладки нужны новые индексы
из `ensure-indexes.ts` для списков подборок и отзыва копий. Пользовательские
коллекции не входят в выкладку корпуса; рабочие данные пользователей не заменяются.

Итог после переноса храма: 1 379 тестов прошли, два пропущены; ошибок нет. `npm run typecheck` и
обычная `next build` прошли. В финальной production-проверке подборка из двух
чтений сохранена вместе с отдельной офлайн-страницей. После отключения тестового
адреса страница перезагрузилась из кэша, исходный порядок двух ссылок сохранился,
обе страницы были показаны как сохранённые. Временные пользователи и их записи
удалены после проверок. Настоящие мобильные устройства и Safari остаются
предрелизной ручной проверкой.


## «Мой храм» в учётной записи

Выбор хранится в `typikon-users.users.myTempleSlug`. Публичные страницы храмов
и дней остаются общими: сессию и выбор загружает клиентский провайдер. Профиль,
«Сегодня», кнопка карточки и отметка престольного праздника используют один выбор.
При входе другого пользователя предыдущее значение сразу скрывается. Выбор
обновляется при возврате во вкладку; вкладки одного браузера сообщают об изменении
через BroadcastChannel. В браузере гостя по-прежнему используется прежний ключ
`typikon:my-temple`; выбор из учётной записи в него не записывается.

В пустой учётной записи профиль и «Сегодня» предлагают перенести старый выбор
браузера. Перенос выполняется только по нажатию и атомарно, если поля ещё нет.
Существующий выбор другого устройства не перезаписывается. После переноса старый
ключ удаляется. Очистка сохраняет явный `null`, поэтому запоздавший перенос не
восстанавливает удалённый выбор. Если храм исчез из каталога, это показано явно;
можно убрать недоступный выбор и выбрать новый.

`GET/POST /api/my-temple` требуют сессию и возвращают `private, no-store`.
Владелец определяется сессией, название и место — каталогом. Принимается только
slug существующего храма или очистка; выбор не даёт приходских прав. Клиент
проверяет владельца ответа; запись со страницы старого входа отклоняется до
изменения данных. Универсальный редактор профиля по-прежнему не принимает это
поле. Дополнительный индекс не нужен: запрос выполняется по `_id` пользователя.

Проверено на двух временных пользователях: изоляция, подмена имени/ID в запросе,
неверные и отсутствующие храмы, приоритет учётной записи, смена и очистка,
защита явного удаления и гонка двух переносов. В браузере проверены гостевой
выбор, предложение переноса после входа, перенос через профиль, сохранение после
перезагрузки, смена в карточке и общий выбор в «Сегодня», очистка и открытие
профиля после неё. Напоминания этим изменением не включаются.

Дополнительно проверены смена входа (запись со старым ожидаемым владельцем
отклоняется без изменения выбора), типы и ESLint новых файлов. Обычная
production-сборка прошла; временная сборка и копия окружения удалены.

## Напоминания по личному плану в приложении

Реализованы локально сервер, форма сайта и Android/Flutter-клиент
`/Users/georgecarpow/StudioProjects/Typikon`. Выбираются время до минуты, дни
недели и часовой пояс IANA. Напоминание ведёт к очередному чтению; оно заново
проверяется сервером при получении и открытии, поэтому отметка о прочтении
на другом устройстве учитывается. Приложение открывает текст или выбранную
статию внутри личного плана. План пока создаётся на сайте.

Пауза и завершение прекращают отправку; при возобновлении сохраняется расписание.
Смена настроек отменяет старые сигналы. Задержки допускаются в пределах часа,
пропущенные дни не догоняются. Атомарная запись на план, местную дату и устройство
защищает от повторов при параллельных запусках. Повторная доставка сигнала также
проверяется приложением. Через FCM передаются только вид сигнала и случайный
идентификатор доставки; текст и текущий статус приложение получает по сессии.
Выход, смена учётной записи и старые уведомления не дают открыть чужой план.

В приложении: «Настройки → Личный план чтения», подключение этого телефона,
разрешение уведомлений, затем сохранение расписания. Старые приложения не
получают новый вид сигнала. Расписание общее для учётной записи, доставка —
подключённым устройствам. Нужны сеть и разрешение Android; доставка при принудительно
остановленном приложении не гарантируется. Проверка на физическом телефоне с
реальным FCM остаётся предрелизной ручной проверкой.

При выкладке нужны обновлённое приложение, `npm run db:indexes` и ежеминутный
запуск из текущей версии сайта: `npm run push:reading-plan -- --send`.
Без `--send` команда только считает подходящие планы и устройства, не записывает
доставки и не отправляет push. Используется существующая служебная учётная запись
FCM. `readingPlanDeliveries` очищается TTL-индексом через неделю; пользовательские
планы и устройства не входят в выкладку корпуса. Крон и реальная отправка в
ходе локальной разработки не включались.

Проверены расчёт времени/дней/поясов, переход даты UTC и повторный час DST,
пауза и завершение; в отдельной временной локальной базе — параллельные отправители,
сухой запуск, исключение старых устройств и пауза между отправками устройствам.
В приложении проверены переход по уведомлению, подавление устаревшего сигнала,
повторная доставка, смена владельца и обновление сессии того же владельца.

Подписки устройства разделены: подключение плана не включает серверный помянник.
Переход помянника на локальные уведомления сохраняет push для личного плана.
Поле `pomyannikEnabled=false` учитывает только новый выбор; старые клиенты
сохраняют прежнее поведение. Проверено фиктивным устройством в локальной базе,
без отправки FCM. Также проверены API: владельцы, приватный ответ, валидация,
конфликт ревизии, переход к следующему чтению, пауза/возобновление и отключение.
В браузере расписание сохранилось после перезагрузки, пауза показана явно.

Итоговые проверки: `typecheck` прошёл, ESLint новых файлов без предупреждений;
19 связанных Flutter-тестов прошли, итоговый debug APK собран. В полной серии
1 382 теста прошли, два пропущены; один тест выкладки получил `spawnSync bash
ETIMEDOUT` при параллельной нагрузке, отдельный повтор прошёл (1/1). Пропусков
или ошибок в тестах напоминаний нет. Анализатор Flutter ошибок и предупреждений
не нашёл, остаются информационные замечания по стилю. Тестовые пользователи,
планы, доставки, фиктивное устройство и прокси удалены. На прод изменений нет.

Обычная production-сборка финального кода сайта прошла в изолированной папке.
Временная сборка и копия окружения удалены; работающий dev-сервер сохранён.
