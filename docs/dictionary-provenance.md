# Единый учёт источников словаря

Учёт хранится отдельно от `lexems`: существующие ObjectId, схемы, формы и редакторские поля не изменяются. Подготовка локальная; подключения к MongoDB у сборщика нет.

## Модель

`sources` описывает источник или неизвестное происхождение, `versions` — конкретный файл с SHA-256 и каналом поступления. Поляков один и тот же источник для старого CSV и слоя `gr` Chu-Rus. Сам Chu-Rus — сборник, а не независимое подтверждение всех его материалов.

`targets` адресует лексему, конкретную форму, значение или назначение схемы. Служебные виды `source-record` и `sense-candidate` сохраняют материал, который ещё нельзя отождествить с канонической статьёй или отдельным значением. Области: `current`, `prepared`, `source`, `historical`. Назначение схемы включает её код: историческое N1t не становится свидетельством для нынешнего N1t*.

`evidence` связывает объект с источником, версией носителя и точным местом: строкой/столбцом CSV, статьёй/фрагментом DSL, слотом снимка. Различаются `dictionary`, `reported-corpus`, `corpus`, `editorial`, `generated`, `unknown`; атрибуция — `exact-match`, `reported`, `reconstructed`, `unknown`. `reportedSourceId` не равен `verifiedPrimarySourceId`. Сверка старого словаря подтверждает совпадение с CSV, а не колляцию с печатным изданием Полякова.

`links` хранит предложенные и проверенные связи. Предложения Chu-Rus не становятся подтверждённой идентификацией омонимов. Читатель возвращает сами связи со статусами и не обходит через них в соседние канонические статьи. Один объект может иметь несколько свидетельств; число файлов или каналов не равно числу независимых первоисточников.

Идентичность форм сохраняет точное написание, грамматические признаки и владельца. Гражданская нормализация не используется для ID. Одинаковые слоты форм объединяются в объект, исходные позиции остаются отдельными свидетельствами. Неизвестный источник представлен явным `source:unknown`; неизвестные библиографические метки Chu-Rus сохраняются дословно с `bibliographyStatus=unknown`.

## Заполнение

Старый CSV сопоставляется по лемме, признакам и полному содержимому. Единственная лемма с изменённой схемой сопоставляется по имени и признакам, после чего каждое поле сверяется отдельно. При неоднозначности источник не угадывается. Технические пустые и webmaster-записи сохранены с неизвестным происхождением.

Из Chu-Rus учитываются все исходные статьи и фрагменты, грамматические связи, 142 подготовленные лексемы раздела я, их формы и назначения схем. Редакторская реконструкция заголовков и 11 схем приписывается проверке восстановления, с контрольной суммой файла решений и исходных данных. Неопределённые схемы явно остаются неизвестными. Нулевая частота и неизвестная частота различаются; положительная частота Chu-Rus не объявляется вхождением в корпус typikon-web.

Пояснительные фрагменты сохраняются как `sense-candidate` со ссылкой на неизменённый текст в исходной SQLite. Это блоки для разбора, не число значений. В старой базе канонических значений нет; они не выдумываются при заполнении источников. Неопознанные и структурные фрагменты сохраняют атрибуцию на исходной записи. При ручном выделении значения создаётся `sense` и свидетельства на соответствующие фрагменты.

Для будущего корпуса модель поддерживает `origin=corpus`, источник текста/издания, версию и locator с позицией токена. Для генератора — `origin=generated`, версию алгоритма и схему/входные данные в locator. Сейчас новые лексемы из корпуса и сгенерированные парадигмы не добавляются.

## Локальная сборка и чтение

Запуск из typikon-web на Node 22:

```sh
node --import tsx src/scripts/build-dictionary-provenance.ts \
  --snapshot ../cs-app/import/current/lexems.json \
  --csv script-data/data.csv \
  --staging ../cs-app/import/chu-rus.sqlite \
  --recovery ../cs-app/import/recovery-ya.reviewed.json \
  --review src/data/dictionary/recovery-review.json \
  --plan ../cs-app/import/plan-current-final.json \
  --out ../cs-app/import/provenance-v1.sqlite

node --import tsx src/scripts/read-dictionary-provenance.ts \
  --db ../cs-app/import/provenance-v1.sqlite \
  --lexeme 68399a217310e32be5d7ad30
```

Существующий результат не перезаписывается. Сборщик проверяет контрольные суммы плана, снимка, подготовленных лексем, Chu-Rus staging и сохранность всех входных файлов. Статус `complete` присваивается только завершённому реестру. Рядом создаётся сводка с SHA-256 результата.

## Подготовленный импорт, без применения

`apply-chu-rus.ts` теперь требует при `--apply` дополнительные `--provenance` и `--provenance-sha256`. Проверяются завершённость реестра, ID плана, fingerprint старого словаря и версия Chu-Rus. Перед записью сохраняются резервные копии пяти новых коллекций `dictionaryProvenanceSources`, `dictionaryProvenanceVersions`, `dictionaryProvenanceTargets`, `dictionaryProvenanceEvidence`, `dictionaryProvenanceLinks` вместе с ранее предусмотренными коллекциями.

Документы добавляются только через `$setOnInsert`. Несовпадение хеша при существующем ID останавливает применение; редакторские поля не перезаписываются. Журнал фиксирует SHA-256 реестра: возобновить тот же импорт с другим реестром нельзя. Изменение канонических записей после снимка требует нового плана. Уже завершённый импорт без этого реестра потребует отдельной миграции, а не молчаливого повторного запуска.

Локальная сборка не выполняет выкладку и запись в рабочую базу. Применение — отдельный этап после выпуска читателя, проверки работающего процесса и повторной сверки базы. Ранее собранный пакет выкладки не включает эти изменения и перед релизом должен быть пересобран.
