# Группы помянника

Группа — самостоятельная сущность в `typikon-users.pomyannikGroups`: `_id`, `userId`, `name`, `key`, `createdAt`. Она существует и без записей. Уникальный индекс `(userId,key)` не допускает дубликатов названия в одном аккаунте; регистр, ударения и ё/е не создают отдельную группу. Название содержит 1–40 знаков; запятые являются частью названия.

В `pomyannikPersons.groups` хранятся ID, а не названия. Ответы личных API содержат также вычисляемое `groupNames`; это поле не принимается на запись. `GET /api/v2/pomyannik/book` возвращает отдельный каталог `groups:[{id,name}]`. Выбор группы в поминовении и закладке чтения использует ID. В карточке группы выбираются флажками. Формат старого приложения с названиями в поле `groups` не поддерживается.

## Создание и массовое добавление

На странице `/pomyannik` кнопка «Группы — создать и добавить имена» открывает создание группы и массовые операции. Поиск, группа и раздел определяют результаты. Можно отмечать отдельные записи или выбрать все результаты, включая страницы, не показанные сейчас. При изменении фильтров выбор очищается. Добавление дополняет членство, не меняя остальные группы, имя, даты и другие поля.

- `GET /api/pomyannik/groups` → `{groups:[{id,name}]}`.
- `POST /api/pomyannik/groups`, `{name}` → `{group:{id,name}}`. Повторное создание того же названия возвращает существующую группу.
- `POST /api/pomyannik/groups/members`, `{groupId,personIds}` → `{items:[{id,groups}],added,skipped:[id]}`.
- Аналогичные ручки `/api/v2/pomyannik/groups` и `/groups/members` требуют scope `pomyannik` и сессию пользователя.

Группа и все выбранные записи проверяются по владельцу до записи. Чужие, удалённые, повторяющиеся и несуществующие ID не отбрасываются молча: запрос отвергается. Для гонки после проверки каждая запись обновляется только в области владельца и только если она активна; не добавленные ID возвращаются в `skipped`. Предел — десять групп на запись, до 10 000 выбранных записей. Повторное добавление безопасно: `$addToSet` не создаёт дубликаты. Все ответы личные (`private, no-store`).

## Перенос данных сайта

При первом обращении аккаунта выполняется однократный перенос названий в ID. Состав сохраняется и в активных записях, и в корзине; выбранные группы в пяти местах чтения и в закладке переводятся в те же ID. Сначала создаётся реестр, затем меняются ссылки. Условие по прежнему массиву и `groupsSchemaVersion` не позволяет перезаписать параллельную правку. Контрольная отметка `pomyannikSettings.groupsVersion=1` появляется только после обработки всех записей. Незавершённый перенос можно повторить: ID детерминированы в рамках владельца, уже перенесённые документы пропускаются.

Сериализация API после переноса работает только с новой схемой. Это перенос существующих данных, а не поддержка двух форматов запросов приложения.

Резервная копия остаётся переносимой между аккаунтами: в ней группы записаны названиями и имеется корневой список `groups`, включающий пустые группы. При восстановлении реестр аккаунта создаёт свои ID, а состав восстанавливается по названиям. Повторное восстановление не добавляет копии тех же записей. Файлы прежнего формата резервных копий остаются читаемыми.
