# Помянник в Android-приложении

Настройки чтения общие для портала и приложения: аккаунт хранит пять независимых мест (`psalter-1…3`, `morning-living`, `morning-departed`). Контракт выбора групп описан в [prayer-circle.md](prayer-circle.md). Полная кафизма и чтение «Подряд» вставляют соответствующий состав после каждой статьи, в том числе трижды внутри псалма 118. По умолчанию: живые, усопшие, без имён. Отдельный переключатель заупокойного окончания отвечает за тропари и молитвы после кафизмы.

## Чин и временная помета

- `rank` — чин/статус: младенец, иерей, архимандрит и др.
- `mark` — независимая временная помета: болящий, путешествующий, заключённый, непраздная, новопреставленный.
- `rankUntil` — последний день действия временной пометы включительно, `YYYY-MM-DD`; отсутствие срока означает отсутствие ручного ограничения.
- Если полной датой указано преставление и нет ручной временной пометы, новопреставленный определяется автоматически до сорокового дня включительно. Неполной даты для такого расчёта недостаточно.

Миграция MongoDB не нужна. Старое временное значение `rank` читается как помета, если `mark` отсутствует. Явный `mark:null` отличается от отсутствия поля. Новый редактор сохраняет отдельно статус и помету, старые клиенты не стирают неизвестные им поля при PUT. Истёкшая помета остаётся в карточке, но не участвует в чтении и новых записках. В API словаря категории имеют `category:status|temporary`; сериализация лица дополнительно возвращает `statusRank`, `mark`, `activeMark`, `activeRanks`. Старые `rank` и `activeRank` сохранены. Снимок новой записки содержит обе категории (`marks`), личная подпись туда не попадает.

## Личные эндпойнты v2

Все требуют scope `pomyannik` и пользовательскую сессию; ответы `private, no-store`. Пользователь берётся из сессии, идентификатор владельца не принимается из тела.

| Эндпойнт | Назначение |
| --- | --- |
| `GET /pomyannik/book` | Все активные лица, ЦС формы из словаря и настройки помянника. `slavonic:{text,genitive,source}`, `settings:{showSignatures,readingPlace,commemorations}` |
| `PUT /pomyannik/book` | `{action:signatures,value:boolean}`, `{action:reading,place:{personId,group,kind}|null}` или `{action:order,ids:[полная перестановка]}` |
| `GET /pomyannik/trash` | `{items:[удалённые лица с deletedAt]}` |
| `POST /pomyannik/trash` | `{id}` — восстановить собственную запись; лимит активных имён учитывается |
| `GET /pomyannik/backup` | Переносимая резервная копия формата `typikon-pomyannik` |
| `POST /pomyannik/restore` | Резервная копия в теле, до 64 МБ; добавление без перезаписи имеющегося; ответ `{added,skipped}` |
| `GET /pomyannik/morning?lang=cu&gender=m` | Утренние молитвы в книжном порядке с именами по настройкам двух мест |

Удаление существующим `DELETE /pomyannik/persons/:id` перемещает имя в корзину. Ни веб, ни приложение не очищают её автоматически. Активный потолок — 10 000 записей, пакет массового ввода — 500. Поля `signature`, `groups`, неполные даты передаются существующими POST/PUT лиц.

## Виды и офлайн

Приложение показывает «Записи», «Просмотр ЦС» и «Чтение». ЦС вид использует серверный родительный падеж, обе действующие категории и подпись, если она включена. Для имени вне словаря показана оговорка о неподтверждённом склонении. Гражданские формы категорий не выдаются за подтверждённые ЦС формы. Настройка подписей, порядок и место чтения синхронизируются с сайтом.

Молитвы никогда не кладутся в общий HTTP-кэш. Личные снимки разделены по аккаунту, полу молящегося и месту; утренние — также по языку. После сетевой ошибки сохранённый состав помечается как необновлённый. Пустая группа и отключённое место не подменяются всем помянником. При смене аккаунта во время запроса ответ отбрасывается. Сохранение новых настроек в приложении очищает прежние снимки этого аккаунта. Без снимка утреннее последование остаётся доступным как книжный текст с явным сообщением об отсутствии личных имён.

Печать выбранного раздела/группы/поиска использует Android PrintManager: HTML со встроенным шрифтом Мономах, без JavaScript и сетевых загрузок. Восстановление файла требует явного подтверждения на экране приложения. Экспорт открывает системное меню сохранения/передачи JSON. Эти функции не означают отправку записки на поминовение.

Изменения сами по себе не публикуют сервер, APK и версию обновления приложения.
