## Исправления по результатам проверки

1. **Публикация после смены native ID.** Старый код загружал пилотное песнопение
   по прежнему номеру SQLite; тест воспроизвёл конфликт алиаса при регистрации
   другого источника. Теперь существующий пилот сначала разрешается по постоянному
   public ID и привязке новой сборки.
2. **Сопоставление дублей.** Прежний последовательный алгоритм мог отдать старый
   ID первому из нескольких новых дублей. Теперь выполняется глобальное взаимно
   однозначное сопоставление: точное, затем по единственному оставшемуся контексту.
   Используются сигнатуры предыдущей сборки, а не только первой записи.
3. **Паспортные ревизии.** Digest приведён к согласованному passport-r1 —
   отсортированным ссылкам на версии метаданных. Изменение записи без новой ревизии
   блокируется. Необязательный `passportDescriptor` добавлен в OpenAPI; summary fields
   также версионируются. Прежние паспорта Э1-08 сохранены и проверены по старым адресам.
4. **Отказы и смешивание версий.** Добавлены проверка bodyId фрагмента, статусы
   удаления, привязка cursor к сборке/окну и защита редакторской истории от
   перезаписи импортом. Обновляется только указатель на успешно проверенную публикацию.

ID пяти источников и их текстовые sr1 после исправлений **не изменились**.
Обновились паспортные ревизии; все пять прежних pr1 остаются доступными.

`release1_9d2ed865b46dfea66061852d822c9a3d11fc1306344cddeab5f4b93f715cc208`.

```sh

  --previous-report ../cs-app/qa/reader-pilot-publication.json \
  --report /tmp/reader-real-pilot.json
```

Изолированная приёмка создаёт отдельную MongoDB с UUID и четыре настоящих
SQLite-файла с синтетическими текстами и изменяемой нумерацией; после тестов
они удаляются. Она не запускает полный технологический сборщик typikon-rules
и не подменяет рабочий RULES_DB. Скрипт reader-acceptance читает реальный пилот
**без записи**; повторная публикация проверяется в изолированном контуре.

В cs-app:

```sh
flutter test test/reader_contract_test.dart
flutter analyze lib/features/reader/domain/reader_packet.dart test/reader_contract_test.dart
```

Dart-декодер сохраняет неизвестные поля и коды ошибок, проверяет принадлежность
снимка, карты, токенов и проекций, различает абсолютные raw и локальные view offsets.
UI и repository приложения на новый API ещё не переключены. Клиентские проверки
не заменяют серверную проверку digest и источниковых свидетельств.

Итог: **61 backend unit/contract test, 15 изолированных сценариев, 6 Flutter-тестов**;
TypeScript и Flutter analyze проходят. Скомпилированы 80 DTO-схем, проверены
13 успешных wire-примеров, 7 ошибок, 6 структурно неверных пакетов и 4
структурно допустимых, но семантически неверных ответа.

Отчёты текущей проверки сохранены в cs-app/qa/reader-e109-*.json.

## Границы результата

Это техническая проверка сохранности данных и адресов, а не историческая
экспертиза авторства. Реальных новых авторов, дат, переводчиков и родного канона
не установлено; синтетические атрибуции не импортированы в пилот. Восстановление
старого тела без сохранённого архивного артефакта не обещается: корректный результат
в этом случае — 410. Android App Links и экран чтения остаются следующими этапами.
Пилот по-прежнему находится только в «Опытах», без главной и индексации.
