# Э1-10: Маргарит через study/material

Дата: **14 ноября 2026 года**. Статус: **подключено и проверено на локальном
тестовом контуре**. Вход — `/opyty/cs-reader/margarit`, ссылка из
`/opyty/cs-reader`. Главная, основная навигация и sitemap не расширялись;
экспериментальная страница имеет noindex.

## Результат

Первая беседа Маргарита открывается в **существующем читателе /study**:
его отображение текста, оглавление, выделения и заметки переиспользованы.
Для опыта добавлен паспорт с источниками и открытыми вопросами, постоянный
адрес, закреплённая ссылка на версию и адрес фрагмента.

- native text: `699c9ace0c51f1c698ea0492`, прежний alias `margarit-1`;
- sourceId: `src_9d0454d1a69b45939d7ebce42dd717ad`;
- sourceRevision: `sr1_7631ec649c67932115fa5128737bd6606d33182b06ada64e31047f96ca31b1fc`;
- fragmentId: `frg_00fdc641f2fb4efaa5fece8a0eed5d4a`;
- постоянный путь: `/sources/id/src_9d0454d1a69b45939d7ebce42dd717ad`.

Фрагмент здесь — **глава целиком**, то есть уже зарегистрированная родная
единица источника. Это явно подписано в интерфейсе. Отдельные абзацы/цитаты
пока используют прежние StudyTarget; новые paragraph fragmentId не выдаются.

Текст по-прежнему читается из исходной Mongo `texts`. Реестр используется
для ID, ревизий и метаданных; новая копия content не создаётся. Исходный SHA
остался `9b908856543a0c9930d633d2c5f57337151fd38d19c29fca9b7a65224612896f`.
Указатель активной публикации Э1-09 не менялся.

## API и совместимость

`GET/POST /api/v2/study/material` остаётся deprecated и сохраняет прежний ответ
по умолчанию. Для тестового подключения введён **явный opt-in** `reader=pilot`:
GET — query-параметр, POST — поле JSON рядом с target.

```sh
curl --get 'http://127.0.0.1:3127/api/v2/study/material' \
  --data-urlencode 'reader=pilot' \
  --data-urlencode 'target={"kind":"text","id":"699c9ace0c51f1c698ea0492"}'
```

В ответ добавляется только необязательное поле **reader**:

- contract `cs-reader/1`, sourceId, pinned address и snapshot;
- bodyRef исходной главы;
- permanentUrl, versionUrl, адрес/URL фрагмента;
- полный паспорт той же passportRevision и ссылка на passport API;
- editorialStatus исходной публикации.

В reader нет второго тела текста. Старые target, sourceHash FNV, blocks,
metadata, footnotes и missing не переименованы и не заменены новыми хешами.
Ответ без reader сохраняет прежние JSON-поля и значения для выбранной главы.
Новые клиенты берут атрибуцию из паспорта: прежнее поле author сохранено для
совместимости и не становится исторически проверенным авторством главы.

Мост разрешает материал через общий ReaderService и сверяет **исходный raw**
с опубликованным bodyRevision. Непубликованная правка → 410, закрытый источник
→ 404, неподдержанный опыт → 422. Повреждённая/отсутствующая привязка не
маскируется успехом. Другая статия, не совпадающая с целой главой, не получает
её паспорт как будто это те же байты.

StudyReaderAttachment и StudyMaterialWithReader описаны в общем OpenAPI;
схемы ссылаются на согласованные reader/v1 DTO. Старый маршрут сохраняет
Deprecation и ссылку на миграцию. Study-ответам не назначается общая лицензия
через deprecation middleware.

## Интерфейс

Экспериментальная страница получает паспорт через настоящий study/material
POST с reader=pilot. Включение не затрагивает обычный /study. В режиме пилота
ответ читается из сети отдельно от старого offline-кэша; устаревшая сохранённая
копия не подставляется как актуальный паспорт.

Ссылки в интерфейсе остаются внутри текущего контура. Канонический URL в API
сохраняет общий домен портала; локальная страница не отправляет пользователя
с тестовым sourceId на production.

Видны:

- кандидатная атрибуция, унаследованная от сборника;
- неизвестный переводчик и отсутствие установленной даты создания/перевода;
- статус texted и незавершённая вычитка;
- источники, наблюдения, утверждения и открытые исследовательские вопросы.

## Проверка

Реальный HTTP-сценарий проверил GET/POST, равенство прежних полей ответа,
StudyMaterialWithReader schema, паспорт, fragment URL, resolver, reader/read,
неизменный raw, deprecated/no-store и отсутствие автоматической лицензии.
Главная и sitemap проверены на отсутствие новой ссылки. Все проверки прошли.

В браузере проверены загрузка главы в существующем читателе, видимый паспорт
и переход к фрагменту по закреплённым source/passport revision.

Изолированный сценарий проверил подключение, правку и закрытие текста:
старый material продолжает выдавать текущее тело, а опциональный паспорт
отказывается сопоставлять его с прежней публикацией. Чужой тип источника
не подключается к этому опыту.

61 unit/contract test и **16 изолированных сценариев** проходят;
TypeScript проверен с `--noEmit --incremental false`.

## Границы и переход к Э2

Э1-10 технически завершён: один существующий текст читается через study/material,
паспорт и адреса согласованы с reader/v1. Базовая модель для этого не менялась.
Условие начала Э2 выполнено в тестовом контуре.

Историческая атрибуция, датировки и вычитка не завершены; granular fragment IDs,
переход Flutter UI, офлайн-паспорта и production-релиз остаются дальнейшей работой.
Пилот остаётся только в «Опытах», без размещения на главной.
