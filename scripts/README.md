# Скрипты выкладки

Два семейства, и различать их важно:

- **`release-*.sh`, `*-release.sh`, `download-db.sh`** — запускаются на РАБОЧЕЙ
  машине. Они собирают то, что едет, кладут его на сервер и запускают там вторую
  половину.
- **`*-remote.sh`** — исполняются НА СЕРВЕРЕ: скармливаются ему через
  `ssh … bash -s` и руками не нужны. Всё, что им требуется знать, приходит
  переменными в той же строке (`REMOTE_ROOT`, `PART`, `RULES_DB_REMOTE`).

Особняком — `mongod_dump.sh` (снятие резервной копии, живёт на сервере в кроне) и
`check-tts-endpoints.sh` (разовая проверка доступности чужих служб).

## Цель выкладки

[release-target.sh](release-target.sh) подключается первой строкой каждого
скрипта первого семейства. Он выбирает цель и настраивает под неё пути.

Доступы лежат по файлу на цель, в корне проекта: `.env.release.prod`,
`.env.release.test` и сколько заведут ещё. Образец со всеми возможными полями —
[.env.release.example](../.env.release.example).

```
npm run release                              # prod (умолчание)
npm run release -- --target test
TARGET=test npm run release:db               # то же переменной окружения
TARGET=test npm run release:db -- bible_verses
bash scripts/release-app.sh --target test 1.6.0 ~/Downloads/app-release.apk
```

Ключ — любое слово, под которое заведён файл: `prod` и `test` нигде не
перечислены. Проверяется наличие файла, а не имя, поэтому опечатка (`--target
tset`) останавливает выкладку, а не уводит её на прод по умолчанию.

Умолчание — `prod`, чтобы не ломать привычные команды. Защитой служит не оно, а
строка, которую каждый скрипт печатает до первого действия:

```
── выкладка: test (admin@10.0.0.5:/srv/typikon), окружение .env.production.test
```

## Откуда они работают

Лежат скрипты здесь, а работают из КОРНЯ ПРОЕКТА: там `.env.production`,
`nobles.db`, выгрузка корпуса и файлы доступов. Переход в корень делает
`release-target.sh`, он же оставляет путь к самим скриптам в `RELEASE_DIR` — для
тех мест, где один скрипт зовёт другого или отправляет его на сервер.

Поэтому запускать их можно откуда угодно: `npm run release`, `bash
scripts/release.sh`, `cd scripts && bash release.sh` — все три равнозначны.

## Что можно задать в файле цели

| Переменная | По умолчанию | Зачем |
|---|---|---|
| `USERNAME`, `PASSWORD`, `HOST` | — | обязательные доступы |
| `REMOTE_ROOT` | `/var/www/typikon.su/typikon-web` | каталог сайта; из него выводятся остальные |
| `ORDO_REMOTE` | рядом с каталогом сайта | служба сборки последования |
| `DUMP_REMOTE` | `/var/www/typikon-data` | выгрузка корпуса |
| `APP_REMOTE` | `/var/www/typikon-app-releases` | сборки приложения |
| `ENV_FILE` | `.env.production` | какой местный файл уезжает файлом `.env.production` |
| `SITE_URL` | `https://www.typikon.info` | адрес цели снаружи: сброс кэша устава |

`ENV_FILE` — главное, что стоит задать испытательной машине: свой бот, своё
приложение VK, свой ключ рассылки. Иначе проверка на ней пойдёт от имени
настоящего сайта — посты уйдут в настоящий канал, толчки на настоящие устройства.

## Порядок выкладки

Полное развёртывание с нуля описано в [DEPLOY.md](../DEPLOY.md). Обычная правка:

| Что изменилось | Команда |
|---|---|
| код сайта | `npm run release` |
| код и база | `npm run release:common` |
| база по частям | `npm run release:db -- texts rest` |
| словарь | `npm run release-csl` |
| новости | `bash scripts/news-db-release.sh` |
| правила устава | `npm run release:ustav` |
| только корпус песнопений | `npm run release:rules-db` |
| только код службы устава | `npm run release:ordo` |
| выгрузка корпуса | `npm run release:data` |
| сборка приложения | `bash scripts/release-app.sh X.Y.Z путь.apk` |

## База: снятие и выкладка по частям

- Резервная копия на сервере снимается раз в сутки (`mongod_dump.sh` в кроне) и хранится семь
  дней.
- Локальная копия прода — `npm run sync:db`; выкладка локальной базы — `npm run release:db`.
- Выкладка идёт по частям, по одному ssh-сеансу на тяжёлую коллекцию: одним сеансом
  `mongorestore` не доживал до конца. Части: `dneslov_names`, `bible_verses`, `texts`,
  `temples`, `rest`. Оборвалась одна — повторяется она одна: `npm run release:db -- bible_verses`.
- Словарь (`typikon-csl`) выкладывается отдельно: `npm run release-csl` дампит базу целиком
  (около 88 МБ). Указатель написаний (`spellings`) производный и пересобирается командой
  `npm run cslav:build -- --apply` на рабочей машине; на сервер он приезжает дампом. После
  правки свёртки написаний на сервере нужен `npm run db:search-index`.
- Приходские и пользовательские данные лежат в `typikon-users` и пишутся только на проде:
  `mongorestore --drop` контентной базы их бы стёр. Перенос с прежнего места — `npm run
  parish:move` (на сервере, однократно).
